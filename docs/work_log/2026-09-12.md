## 08:16 — Start | Candela | Bug: brightness/temp silently resets after sleep/conflict; publish + auto-release

## 08:16 — -> Diagnosed root cause
Ran `ps aux | grep redshift` -> 0 procs while `~/.config/candela/settings.json` = {brightness:50, temp_k:4000},
so app saved-state and real display diverged. Root: one-shot `redshift -O` applies ramp once then exits;
ramp is dropped on DPMS sleep/wake, lock, or xrandr events -> nothing re-asserts. Recent commit 2628d49
(startup re-apply) did not help a tray app that runs indefinitely.

## 09:xx — -> Claude Code shipped persistent-daemon fix (commit e91f3c6)
Delegated real code change to Claude Code (flat sub) per Jon's cost rule. It replaced one-shot `-O`
with a long-lived `redshift -l 0:0 -t T:T -b B:B -m randr -P` daemon that re-asserts the ramp across
sleep/wake. Verified: uses SIGKILL (redshift ignores SIGTERM ~4s in continuous mode), cleaned up on
quit/close, bump to 0.1.4. Verdict: real improvement for solo-tool users.

## 09:xx — -> Found TRUE root cause: gamma-tool conflict
Discovered KDE Plasma Night Color is Active=true (kwinrc [NightColor], nightcolorcontrol panel widget,
lat/long for Phoenix). KDE Night Color writes the SAME gamma ramp Candela does -> they fight; whoever
fires last clobbers the other. This (not just sleep/wake) explains "icon shows 50%/4000K but screen is bright."
